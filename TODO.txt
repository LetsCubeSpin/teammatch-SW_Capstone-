[백엔드 1] 담당  —  사용자 / 수업 / 매칭 결과 저장 중심
------------------------------------------------------------

1) DB 구조 설계
   - 회원·학생·과목 데이터 모델 설계
   - 서버 기본 환경 구축
   현재 상태:
   [v] users / classes / enrollments 테이블 설계됨 (db/schema.sql)
   [v] 서버 기본 환경: FastAPI + SQLAlchemy 세팅 완료
       (app/config.py, app/database.py, app/main.py)
   [ ] (선택) MySQL로 갈 경우 schema.mysql.sql 기준으로 모델/드라이버 맞추기

2) 회원/인증 API
   - 회원가입·로그인
   - 사용자 정보 CRUD
   현재 상태:
   [v] 회원가입 POST /api/auth/signup
   [v] 로그인   POST /api/auth/login (JWT 발급)
   [v] 내 정보  GET  /api/auth/me
   [ ] 사용자 정보 "수정/삭제"(Update/Delete)는 아직 없음 -> 추가 필요
       예) PUT /api/auth/me (프로필 수정), 회원 탈퇴

3) 과목/학생 API
   - 과목 생성·수정·삭제
   - 학생 과목 참여/조회
   현재 상태:
   [v] 과목 생성 POST /api/classes
   [v] 과목 목록 GET  /api/classes
   [v] 학생 참여 POST /api/classes/join (참여 코드)
   [v] 명단 조회 GET  /api/classes/{id}/roster
   [ ] 과목 "수정" API 없음 -> PUT /api/classes/{id} 추가 필요
   [ ] 과목 "삭제" API 없음 -> DELETE /api/classes/{id} 추가 필요

4) 매칭 데이터 제공 API
   - 학생 정보 조회
   - 조건 및 제약조건 전달
   현재 상태:
   [v] 매칭 실행 시 설문 제출자 정보를 내부에서 모아 엔진에 전달
       (app/routers/matching.py 의 _load_candidates)
   [v] 가중치/하드 제약조건 전달 구조 있음 (schemas.py: Weights, HardConstraints)
   [ ] 교수가 매칭 전에 "대상 학생/조건을 미리 조회"하는 별도 API는 없음
       -> 필요하면 GET /api/classes/{id}/candidates 추가 고려

5) 매칭 결과 저장 API
   - 매칭 이력 관리
   - 팀 결과 조회
   현재 상태:
   [v] 매칭 실행 결과를 match_runs/teams/team_members에 저장
   [ ] "저장된 결과 다시 조회"하는 API 없음
       -> GET /api/classes/{id}/result (최신 결과)
       -> GET /api/runs/{run_id} (특정 이력) 추가 필요

6) 팀원/학생 정보 API
   - 팀원 상세 정보
   - 일정 정보 조회
   현재 상태:
   [v] 설문에 일정(availability) 저장/조회 있음 (surveys.py)
   [ ] "팀 단위"로 팀원 상세 + 일정을 묶어서 보여주는 API 없음
       -> GET /api/teams/{team_id} 추가 필요

7) 권한/사용자 관리
   - 교수·학생 접근 권한
   - 과목별 접근 제어
   현재 상태:
   [v] 교수/학생 역할 구분 및 권한 강제 (security.py: require_professor/require_student)
   [v] 수업 소유자(교수) 확인 로직 일부 있음 (classes/matching에서 professor_id 체크)
   [ ] 과목별 접근 제어를 모든 엔드포인트에서 일관되게 점검 필요(검토 작업)

8) API 통합 및 예외 처리
   - 인증/권한 오류 수정
   - DB 최적화
   현재 상태:
   [ ] 공통 예외 처리/에러 응답 형식 정리 필요
   [ ] 자주 쓰는 조회에 인덱스/쿼리 점검(일부 인덱스는 schema에 있음)

9) 백엔드 QA
   - API 테스트
   - 보안/권한 점검
   - 성능 개선
   현재 상태:
   [v] 매칭 엔진 단위 테스트 있음 (tests/test_matching.py)
   [ ] API(라우터) 레벨 테스트 없음 -> 로그인/권한/수업 흐름 테스트 추가 필요
   [ ] 보안 점검(토큰 만료, 권한 우회 등) 체크리스트 필요

10) 서버 최종 배포
    - DB/서버 점검
    - 운영 환경 설정
    현재 상태:
